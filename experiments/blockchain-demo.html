MedLedger Storage and Integrity Demo

This page explains the complete reasoning chain for the project: medical content changes alter the content hash, IPFS produces a new CID, peer nodes pin content by CID, and the blockchain anchor becomes invalid if someone rewrites old history instead of appending a new block.

2. Peer-to-Peer Pinning

In a content-addressed network, peers pin objects by CID. They are not storing “the latest version” under the same identifier. A changed record becomes a different object that needs its own CID.

3. Blockchain Anchor and Failure Modes

The chain below anchors the original CID and payload hash. There are two fundamentally different actions:

1. the valid action: append a new block for a new CID

2. the invalid action: rewrite historical block data

If the current CID differs from the anchored CID of block 2, that means the off-chain content changed after the blockchain reference was created.
The correct blockchain behavior is to append a new block with the new CID, not to rewrite an older block. Rewriting history breaks trust.
